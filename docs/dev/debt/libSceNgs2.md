# libSceNgs2 technical debt

### Unknown function info

- [sceNgs2FftQuerySize](../../../core/libs/prx/libSceNgs2/PendingExports.cpp) (libSceNgs2) - implemented in `libSceNgs2.native/src/System.cpp` from the firmware 11.00 module at `0x430`, whose table is at `0x30b30`: lengths 8..12 select 64, 128, 256, 512 and 1024 samples from the entry at offset 4, bit 1 of the flags halves the count, and the work size is `32 * count + 64`. `-1` for a length outside 8..12 is the module's own return; `-1` for a null output is this implementation's guard, since the module writes through the pointer after validating only the length. [sceNgs2FftInit and sceNgs2FftProcess](../../../core/libs/prx/libSceNgs2/PendingExports.cpp) still throw: the 7.3 KB AVX radix-8 kernel and its packed input/output layout are not recovered, and no dump imports these NIDs.
- [sceNgs2ParseWaveformUser, sceNgs2SystemEnumHandles, sceNgs2SystemEnumRackHandles](../../../core/libs/prx/libSceNgs2/PendingExports.cpp) (libSceNgs2) - implemented in `libSceNgs2.native/src/System.cpp` from the firmware 11.00 module at `0x10810`, `0xf270` and `0xf0d0`. `sceNgs2ParseWaveformUser` passes a type-2 read descriptor to the module helper at `0xfac0`, which calls the handler as `handler(user_data, offset, data, size)` and expects an `int32_t`; in the module a negative return becomes `0x804A0408`, as does a null handler, and a null output becomes `0x804A0053`. The 256 MiB RIFF cap, which returns `SCE_NGS2_ERROR_INVALID_WAVEFORM_DATA`, and buffering the whole RIFF body after the 12-byte header are this implementation's safety choices, not measured on a console. The enumerators return the count of live systems or racks and fill up to the requested count; a null output with a nonzero count returns `0x804A0053` and an unknown system `0x804A0230`. No dump imports these NIDs.
- [Custom Delay module parameters](../../../core/libs/prx/libSceNgs2.native/src/Custom.cpp) (libSceNgs2.native) - the setter accepts a delay parameter record (id 0x40001d00, seen at 264 bytes: size/next/id header, then 1.0/0.0/1.0/0.0, 4000.0 and 4, tap gains 0.7/0.5/0.3/0.1 at an eight-byte stride, and 8 and 1 in the tail) and does not apply it. The Delay module is already skipped in processing, so audio passes through unprocessed; this setter used to throw and ended the title at the Years 1-4 selection. Applying the delay line is open work, and the field meanings above are inferred from one title's values, not measured.
- [PS4 rack option layout](../../../core/libs/prx/libSceNgs2.native/src/Rack.cpp) (libSceNgs2) - a PS4 process (title id starting `CUSA`, as `libkernel_sys` already decides) receives a different `Ngs2RackOption` from the native one: `size_t size`, `char name[16]`, eight `uint32_t` counts and `reserved[18]`, 128 bytes in total, so the sampler option is 168 bytes, submixer 152, mastering 136 and reverb 136, while the native option keeps a 64-byte name and is 176 bytes. The library keeps the native structs internally and converts the PS4 bytes (common fields by name, the rack-specific tail from offset 128 to offset 176); the wire size is picked at runtime from the process title id, because a PS5 title loads `libSceNgs2.prx` too and sends the 216-byte native sampler option. A LEGO Harry Potter PS4 launcher passes a 136-byte mastering option (name `d11-master`, all common counts zero, `max_channels` 8, `num_peak_meter_blocks` 8) and a 168-byte sampler option (name `d11-voices`, flags 0x40000000, 256 grain samples, 256 voices, 2 matrices, 8 ports, `max_channel_works` 256, `max_codec_caches` 32, 4 waveform blocks, 4 envelope points, 8 filters, 256 ATRAC9 decoders and channel works, 8 peak-meter blocks). The field offsets come from that one option pair; no console was measured. Only sampler racks now require `max_voices > 0`, because the mastering option legitimately passes 0. `APS5_NGS2_TRACE_PARAMS=1` prints a rejected option and its bytes.
